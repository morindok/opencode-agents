REFERENCE PYTHON CLIENT (inline template - adapt per request):
```python
import requests
S = requests.Session()
S.headers.update({"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
 "Accept": "application/json", "Referer": "https://www.bybit.com/"})
BYBIT = ["https://api.bybit.com", "https://api.bytick.com", "https://api.bybit.kz"]
_active = {"url": None}

def bybit_get(path, params, timeout=10):
 cands = ([_active["url"]] if _active["url"] else []) + [b for b in BYBIT if b != _active["url"]]
 for base in cands:
 try:
 r = S.get(f"{base}{path}", params=params, timeout=timeout)
 if r.status_code in (403, 451): continue
 r.raise_for_status(); d = r.json()
 if d.get("retCode") == 0:
 _active["url"] = base; return d
 except Exception: continue
 return None

def bybit_klines(symbol="BTCUSDT", interval="15", limit=500, category="linear"):
 d = bybit_get("/v5/market/kline", {"category": category, "symbol": symbol, "interval": interval, "limit": limit})
 if not d or not (d.get("result") or {}).get("list"): return None
 lst = sorted(d["result"]["list"], key=lambda x: int(x[0]))
 rows = [{"ts": int(r[0]), "open": float(r[1]), "high": float(r[2]), "low": float(r[3]),
 "close": float(r[4]), "volume": float(r[5]), "turnover": float(r[6])} for r in lst]
 for c in rows: # PROXY buy/sell split by candle direction - label as proxy
 c["buyVol"] = c["volume"] if c["close"] >= c["open"] else 0.0
 c["sellVol"] = c["volume"] - c["buyVol"]
 return rows

def bybit_derivatives(symbol="BTCUSDT"):
 t = bybit_get("/v5/market/tickers", {"category": "linear", "symbol": symbol})
 r = ((t or {}).get("result") or {}).get("list", [{}])[0]
 return {"lastPrice": float(r.get("lastPrice", 0) or 0),
 "fundingRate": float(r.get("fundingRate", 0) or 0),
 "openInterest": float(r.get("openInterest", 0) or 0),
 "volume24h": float(r.get("volume24h", 0) or 0),
 "turnover24h": float(r.get("turnover24h", 0) or 0)}

def bybit_orderbook(symbol="BTCUSDT", limit=50):
 d = bybit_get("/v5/market/orderbook", {"category": "linear", "symbol": symbol, "limit": limit})
 r = (d or {}).get("result") or {}
 return {"bids": r.get("b", []), "asks": r.get("a", [])}
```

ANALYSIS STANDARDS FOR BYBIT DATA:
 Delta analysis: from klines -> candle-color PROXY delta (buyVol sellVol), always labeled proxy. For TRUE taker flow -> use recent-trade endpoint (side field = real aggressor side).
 Trendline/level volume profiling (BITMOON pattern): for any drawn trendline or level - candles closing above vs below the line -> sum buy/sell volume per side -> above_delta, below_delta, net_delta = above_delta below_delta.
 Always compute over CLOSED candles only (drop the last row if unclosed) so numbers change only when a candle closes, not tick-by-tick.
 Derivatives desk always reports from Bybit: funding rate (normal 0.01%/8h; strongly positive = crowded longs), OI trend (rising OI + rising price = new longs; rising OI + falling price = new shorts), basis, and long/short account ratio.
 Cite the data source in every briefing: 'Bybit linear BTCUSDT, interval X, N candles, fetched at HH:MM'.

STEP 3 - BACKTEST PROTOCOL (no self-deception):
 Fees: model Bybit linear perp taker 0.055% per side + slippage 0.02% per side by default (maker 0.02% if limit entries). State assumptions in the report.
 No lookahead: signals computed on closed candle data, execution at NEXT candle open.
 Metrics required: trade count, win rate, profit factor, expectancy per trade (R and %), avg win / avg loss, max drawdown, longest losing streak, total return, Sharpe-style ratio (per-trade).

 Split: in-sample first 70% / out-of-sample last 30%. Parameters may only be tuned on in-sample; OOS result is the honest headline. Also run walk-forward (rolling refit) when trade count allows.
 Robustness: 20% perturbation of each threshold must not flip the sign of expectancy; test long-only vs short-only legs separately.

STEP 4 - STRATEGY SPEC (deliverable):
Report: timeframe & symbol & period covered; regime filter (when strategy is allowed to trade); entry rules (exact, numeric); exit rules (stop, TP, trailing, time-stop); position sizing (risk % per trade, 1-2% default); performance table (IS vs OOS); top 3 failure modes of the strategy; the single market condition that voids it.
